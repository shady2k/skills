# Engineering

Tracked work, proportional design and acceptance of an assembled stage.

## Started on the user's request

- [take-task](./take-task/SKILL.md): preflight with the owner, then run a whole
  feature alone to one pull request, stopping only for decisions that need them
  and telling them unasked what the run's own overhead is costing. Every date stands beside a forecast the run script computes from the measured pace over the tasks that cover it, a duration it speaks is that measurement with its basis and is not renumbered because the owner doubted it, and every worker's brief carries what its task serves, whom it serves and where you see it.
- [ship-release](./ship-release/SKILL.md): carry merged, accepted work to its
  users — version, release notes, migrations with their reverse, rollout by
  environment with the rollback named before each step; through the project's
  own pipeline.
- [handle-incident](./handle-incident/SKILL.md): restore a failing product
  first, then find the cause, then a blameless review whose actions are filed
  as work.
- [refine-practices](./refine-practices/SKILL.md): a retrospective over the
  work since the last one — the classes of error that came back, and the
  practices to add or retire, put to the owner as the project's setting for
  open questions says.

## Started when the work calls for it

Also available directly to the user.

- [to-spec](./to-spec/SKILL.md): proposed deltas to living capability specs,
  short or full according to risk, with scenarios and document readiness checks. A constraint it states is a requirement with a check, and an uncovered one is refused.
- [to-design](./to-design/SKILL.md): how the system will meet an outcome —
  drivers and the shape that exists, options from named patterns traded
  against quality attributes, a recorded decision reviewed before building —
  for changes that change its shape. The design lists its constraints with a check each — a limit of scale is proved only on a fixture at least that size — names the vision principles of its area, and its acceptance carries another model's judgement of what it serves and breaks, each entry an id the vision declares and a passage quoted from the design record.
- [to-prototype](./to-prototype/SKILL.md): bounded runnable evidence for one question.
- [diagnose-bug](./diagnose-bug/SKILL.md): diagnosis with evidence; fixing requires
  an authorized tracked task.
- [model-domain](./model-domain/SKILL.md): glossary, the names of the system's
  own parts, and consequential decisions.
- [describe-repository](./describe-repository/SKILL.md): describes one code
  repository the product spans for its wiki — the model with its evidence,
  the architecture page, the capabilities found in the code as requirements
  and use cases marked derived from code, and the decisions.
- [write-intended-model](./write-intended-model/SKILL.md): writes or checks a
  repository's intended model — the YAML architecture model in the
  repository's model folder, with its review report and rendered views.
